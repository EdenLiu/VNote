# VNote 使用 ChatGPT 账号生成周报与任务推荐

**设计已确认 · 2026-11-27 · Windows 本地桌面版**

用户可以用自己的 ChatGPT 套餐生成周报和 My Day 推荐，无需填写 API Key 或安装 Codex。两项功能共用当前选定的服务。登录是可选操作，普通周报、规则推荐和本地任务管理随时可用。

## 用户从哪里开始

1. 在 **AI 设置**中选择「使用 ChatGPT 登录」或「兼容 API」。已有 API 配置的用户升级后继续使用原配置。新用户也可以在第一次点击「生成周报」或「获取推荐」时就地选择。
2. 选择 ChatGPT 时，VNote 打开系统浏览器。用户在 OpenAI 页面选择账号及工作区，并授权 VNote 使用套餐。VNote 记住发起登录的页面和正在编辑的草稿。
3. 授权返回后，VNote 核对身份、套餐权限和该账号可用的模型。首次成功启用时，提示周报和推荐将使用 ChatGPT 套餐或可用额度，并提供「管理用量」。随后回到原页面，由用户再次点击生成。登录和加载模型名单都不会发送任务。[官方界面指引](https://developers.openai.com/siwc/ui-ux-guidelines)
4. 在生成按钮旁显示当前使用的服务。ChatGPT 模式提供「管理用量」。AI 设置显示当前账号和模型，默认选用服务端排序中的第一个可见模型，用户可另选。更换账号后重新获取模型名单。[官方模型说明](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)

## 账号与服务切换

首版一次连接一个 ChatGPT 账号。**正在尝试连接的账号**与**当前处理任务的服务**分别记录。只有新账号取得套餐权限且有可用模型后，才完成切换。

| 用户遇到的情况 | VNote 的行为 |
| --- | --- |
| 从兼容 API 开始登录，中途取消、超时或拒绝授权 | 回到原页面，原 API 配置仍可用。 |
| 浏览器已登录，只授予身份权限 | 显示「已登录，尚不能使用套餐」和「重新授权」。服务明确返回账号不支持时，提供「更换账号」和「切换到兼容 API」。 |
| 授权后模型列表暂时加载失败或返回空列表 | 保留当前可用服务，解释原因并提供重试。模型列表成功返回后再启用。 |
| 将账号 A 更换为 B | B 完成授权前保留 A。取消时可继续用 A；切换成功后显示 B 的账号和模型，并让 A 的待处理结果失效。 |
| 额度用完、网络失败或会话失效 | 显示原因和对应操作。用户可管理用量、重试、重新连接或手动换用兼容 API。重试需要用户主动发起，原草稿和仍有效的推荐继续可见。 |
| 重启或断开连接 | 重启后恢复选定服务，必要时续期。断开时停止请求、尝试撤销当前会话、清除本地令牌。离线时告知用户远端撤销尚未确认，并提供 ChatGPT 设置入口。 |

切换服务不搬移任务。清单的 AI 读取权限、参与推荐开关和备注授权沿用现有设置。API 的地址、模型和密钥与 ChatGPT 账号配置分开保存。[官方账号与会话说明](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)

## 两种接入方式如何共用业务规则

| 层级 | 设计 |
| --- | --- |
| Electron 主进程登录 | 使用面向本地应用的 **Sign in with ChatGPT**。通过系统浏览器和本机回调完成带 PKCE 的 OAuth 登录，每次校验此次登录的 state、nonce、身份及实际授予的权限。安装实例标识跨重启保留。登录凭据由主进程使用 Windows 保护的本地存储管理。渲染进程只接收连接状态、账号显示信息和模型选项。[官方登录流程](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) |
| 任务服务 | 以现有 `TaskService` 的共享请求入口选择服务。发送前按当前授权筛选清单、My Day 上下文和备注。周报继续由本地确定分组、来源、重复完成次数以及含今天在内的三天到期窗口；推荐仍限零至三项有效候选，只有用户逐项采纳才写入 My Day。 |
| 兼容 API | 沿用已配置的服务地址、模型和 API Key，调用 Chat Completions。 |
| ChatGPT 套餐 | 主进程仅向官方端点使用套餐令牌。用当前账号获取模型目录，通过 `POST https://api.openai.com/v1/responses` 发送请求，设置 `store: false` 和 `stream: true`。主进程接收流，成功结束并通过业务校验后才向界面交付结果。[官方推理协议](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) |

## 生成、编辑与取消

- **周报。** 请求期间保留可编辑草稿并显示「取消」。如果已有手工编辑，或用户在等待时修改了文字，成功后提供「使用新草稿」和「保留我的编辑」。失败、取消、流中断或格式校验失败时保留当前文字。
- **推荐。** 完整结果通过候选来源、去重和理由校验后一次展示。刷新失败时保留同一账号下仍有效的旧推荐及其采纳能力。采纳时再次核对当前账号、任务和授权范围。
- **迟到结果。** 主进程为每次生成记录请求标识、当前服务、账号和数据授权版本。用户取消、切换服务或账号、断开连接、撤回清单或备注授权时，中止受影响的请求。提交结果前再次核对这些条件，旧结果不得覆盖草稿、恢复已失效的推荐或结束新请求的加载状态。取消只能阻止继续使用结果，已经发送的数据无法收回。

现有 `WeeklyReportModal.tsx` 已支持保留手工编辑和选择替代草稿。实现时需扩展主进程与 preload 之间的生成请求，让取消操作能中止实际网络请求。现有 `SuggestionsView.tsx` 和 `TaskService` 在刷新开始时分别清除旧卡片和可采纳记录；两处都应等新批次通过校验后再替换，才能在同账号刷新失败时保住有效推荐。

## 验收

| 验收方式 | 通过标准 |
| --- | --- |
| Windows 安装包与本人真实授权 | 使用只含示例任务的临时数据库。从周报入口用系统浏览器授权，返回时草稿仍在；主动生成一份周报并核对原任务，再生成推荐并采纳一项；退出并重新启动安装包，确认账号连接和已采纳的任务。 |
| 旧版升级和登录异常 | 原 API 配置升级后可直接使用。模拟登录取消、身份成功但缺少套餐权限、套餐不支持、额度用完、会话过期和模型列表失败，逐项核对界面恢复、当前服务和请求目的地。 |
| 编辑与并发 | 生成时编辑、取消后重试、切换账号、撤销清单或备注授权，再让旧响应晚于新响应到达。验证手工编辑受保护，旧结果不会被应用，失效推荐无法采纳。 |
| 两种服务的数据授权 | 分别检查两条路径的出站请求。未授权清单、其中已加入 My Day 的任务，以及未启用的备注均不发送。只登录或打开功能页面时没有任务生成请求。 |

真实账号验收由用户在官方浏览器页面完成授权。开发测试使用模拟服务覆盖异常情况。本文记录已确认的设计；安装包真实登录和生成的结果在实现后登记。
